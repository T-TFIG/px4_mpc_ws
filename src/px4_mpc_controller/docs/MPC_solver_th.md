# การแก้ปัญหา Nonlinear MPC: จากโมเดลสู่ตัวเลข

*(ฉบับแปลภาษาไทยของ `MPC_solver.md` — เนื้อหาตรงกันทุกประการ)*

## เอกสารนี้ครอบคลุมอะไร

`MPC_explanation_my_version.md` อนุพันธ์สมการการเคลื่อนที่ของ quadrotor จากหลักการพื้นฐาน แล้วเขียนปัญหา nonlinear MPC ที่เราต้องการแก้ จากนั้นร่างโครง SQP ที่ใช้แก้มัน (ส่วนที่ V ของเอกสารนั้น) และ loop ที่รันมัน (ส่วนที่ VI)

เอกสารนี้คือครึ่งหลัง มันรับช่วงต่อจากจุดที่โครงนั้นหยุด และตอบคำถามว่า: **เมื่อมีโมเดลไม่เชิงเส้นนั้นแล้ว ตัวแก้ (solver) เปลี่ยนมันเป็นตัวเลขได้อย่างไร 10 หรือ 50 ครั้งต่อวินาที?**

กฎเดียวกับเอกสารคู่กัน: ไม่มีสูตรไหนถูกโยนมาแบบสำเร็จรูป ทุกสมการอนุพันธ์มาจากสมการก่อนหน้า พร้อมคำอธิบายว่ามันมาจากไหนและทำไมขั้นตอนนั้นถึงจำเป็น

**ข้อสังเกตสำคัญเรื่องขอบเขต** เอกสารนี้พูดถึง **โมเดลไม่เชิงเส้นเต็มรูป** — quadrotor แบบ rigid-body 12 states มันไม่ใช่คำอธิบายของสิ่งที่ `mpc_solver.py` implement อยู่ตอนนี้ โค้ดปัจจุบันรันโมเดล point-mass ที่ทำให้ง่ายขึ้น ซึ่งเป็นการทำให้ง่ายขึ้นโดยตั้งใจ ไม่ใช่ความหลงลืม เอกสารนี้อธิบายกลไกที่จำเป็นสำหรับโมเดล *จริง* — สิ่งที่เราจะสร้างต่อไป

ความแตกต่างระหว่างสองอย่างนี้สำคัญมาก และส่วนที่ 6 ทั้งส่วนพูดถึงความแตกต่างนั้น: ปัญหา point-mass เป็น convex QP ที่มีการรับประกันแข็งแรง ส่วนปัญหาไม่เชิงเส้นนั้นไม่ใช่เลย

## ส่วนที่ 1: ปัญหาที่เรากำลังแก้

### 1.1 ทบทวนโมเดล

state และพลศาสตร์ ในรูป Euler-Lagrange ที่เอกสารนี้ใช้ — generalized coordinates $(\xi,\eta)$ กับอัตราของมัน โดยตัดเทอม Coriolis $C(\eta,\dot\eta)$ ทิ้งเป็นการทำให้ง่ายขึ้นที่ประกาศไว้ — คือ:

$$x = \begin{bmatrix}\xi\\\eta\\\dot\xi\\\dot\eta\end{bmatrix}\in\mathbb{R}^{12},
\qquad
\dot x = f(x,u) = \begin{bmatrix}
\dot\xi\\
\dot\eta\\
\frac{1}{m}\big(R(\eta)[0,0,T]^T - [0,0,mg]^T\big)\\
M(\eta)^{-1}W(\eta)^T\tau_{body}
\end{bmatrix}$$

และจากส่วนที่ 6.2 control input ที่แท้จริงคือแรงขับของโรเตอร์สี่ตัว โดย $T$ และ $\tau_{body}$ ได้มาจากมันผ่านเมทริกซ์ mixer คงที่ $\Gamma$:

$$u = \begin{bmatrix}f_1\\f_2\\f_3\\f_4\end{bmatrix},
\qquad
\begin{bmatrix}T\\\tau_\phi\\\tau_\theta\\\tau_\psi\end{bmatrix} = \Gamma u
= \begin{bmatrix}1&1&1&1\\0&l&0&-l\\-l&0&l&0\\c&-c&c&-c\end{bmatrix}
\begin{bmatrix}f_1\\f_2\\f_3\\f_4\end{bmatrix}$$

สิบสอง states, สี่ inputs ทุกอย่างอยู่ใน NED ดังนั้น $\xi_z$ ชี้ *ลง*

### 1.2 อะไรทำให้มันยาก

คุณสมบัติสามข้อของ $f(x,u)$ เป็นตัวขับเคลื่อนทุกอย่างในเอกสารนี้:

1. **มันไม่เชิงเส้น** $R(\eta)$ และ $W(\eta)$ เต็มไปด้วย $\sin$ และ $\cos$ ของตัวแปร state; $M(\eta)$ ก็เช่นกัน และมันต้องถูก *invert* ด้วย ไม่มีทางเขียน $f(x,u) = Ax + Bu$ ได้
2. **มันเชื่อมโยงกัน (coupled)** ความเร่งเชิงเลื่อนที่ขึ้นอยู่กับการวางตัวผ่าน $R(\eta)$; ความเร่งเชิงมุมขึ้นอยู่กับการวางตัวผ่าน $M(\eta)^{-1}$ คุณไม่สามารถแยกปัญหาออกเป็นแกนอิสระได้
3. **มัน underactuated** สี่ inputs, สิบสอง states, หก degrees of freedom โดรนไม่สามารถเร่งไปด้านข้างได้โดยตรง — มันต้องเอียงก่อน ซึ่งใช้เวลา ตัวแก้ต้อง *ค้นพบ* ลำดับนี้เอง

ข้อ 3 คือข้อที่น่าสนใจ มันคือเหตุผลที่ optimizer คุ้มค่า: ห่วงโซ่เหตุและผล "แรงขับ → แรงบิด → ความเร่งเชิงมุม → การเอียง → แรงขับที่เปลี่ยนทิศ → ความเร่งแนวราบ" คือสิ่งที่ตัวแก้ต้องวางแผนผ่าน หลายก้าวล่วงหน้า แทนที่จะคำนวณในรูปปิด

### 1.3 สามสิ่งที่เราต้องสร้าง

เพื่อไปจาก $\dot x = f(x,u)$ สู่ตัวเลขที่เราส่งให้มอเตอร์ได้:

1. **Discretize** — เปลี่ยน ODE ต่อเนื่องเป็นความสัมพันธ์ระหว่างขั้นเวลาที่ติดกัน (ส่วนที่ 2)
2. **Transcribe** — เปลี่ยนปัญหา optimal control ที่มีมิติอนันต์ เป็น nonlinear program ที่มีมิติจำกัด (ส่วนที่ 3-5)
3. **Solve** — หาค่าที่ดีที่สุดของโปรแกรมนั้น เร็วพอที่จะใช้ประโยชน์ได้ (ส่วนที่ 7-11)

## ส่วนที่ 2: Discretization

### 2.1 ทำไมเราทำแบบเดิมไม่ได้

สำหรับโมเดล point-mass การ discretize เป็นแบบ *แม่นยำ (exact)*: double integrator ภายใต้ zero-order hold integrate ได้ในรูปปิด ($p_{k+1} = p_k + v_k\Delta t + \tfrac12 u_k\Delta t^2$) โดยมีความคลาดเคลื่อนจากการตัดทอนเป็นศูนย์ เทียบเท่ากับว่า $\dot x = A_cx + B_cu$ มีคำตอบรูปปิด $x_{k+1} = e^{A_c\Delta t}x_k + \big(\int_0^{\Delta t}e^{A_cs}ds\big)B_cu_k$

เส้นทางนั้นถูกปิดไปแล้วสำหรับเรา $\dot x = f(x,u)$ ที่ $f$ ไม่เชิงเส้น **ไม่มีคำตอบรูปปิดทั่วไป** — ไม่มี matrix exponential ให้เขียน ไม่มี integral ที่เราประเมินเชิงสัญลักษณ์ได้ เราต้อง integrate *เชิงตัวเลข* และการ integrate เชิงตัวเลขหมายถึงการยอมรับความคลาดเคลื่อนบางส่วน คำถามจึงกลายเป็น: คลาดเคลื่อนแค่ไหน แลกกับการคำนวณเท่าไหร่?

### 2.2 ตัวเลือกที่ง่ายที่สุด และทำไมมันไม่พอ

**Forward Euler** ประมาณคำตอบโดยสมมติว่าอนุพันธ์คงที่ตลอดทั้งช่วง:

$$x_{k+1} = x_k + \Delta t\, f(x_k, u_k)$$

กระจายคำตอบจริงเป็นอนุกรมเทย์เลอร์รอบ $t_k$:

$$x(t_k + \Delta t) = x_k + \Delta t\,\dot x_k + \frac{\Delta t^2}{2}\ddot x_k + O(\Delta t^3)$$

Euler จับสองเทอมแรกไว้ และทิ้งทุกอย่างตั้งแต่ $\frac{\Delta t^2}{2}\ddot x_k$ เป็นต้นไป ดังนั้นความคลาดเคลื่อน **เฉพาะที่ (local)** เป็น $O(\Delta t^2)$ เมื่อสะสมตลอด $1/\Delta t$ ขั้น ความคลาดเคลื่อน **รวม (global)** เป็น $O(\Delta t)$ — ความแม่นยำอันดับหนึ่ง

ทำไมนั่นไม่พอที่นี่: พลศาสตร์เชิงหมุนนั้น *เร็ว* การวางตัวตอบสนองในระดับหลายสิบมิลลิวินาที เร็วกว่าการเคลื่อนที่เชิงเลื่อนที่หนึ่งเท่าตัวของ order ด้วย $\Delta t = 0.1\,$วินาที Euler ที่ใช้กับโหมดการหมุนที่เร็วไม่ได้แค่เสียความแม่นยำ แต่มันสามารถ **ไม่เสถียร (unstable)** ได้ — ทำนายการแกว่งที่ลู่ออกแทนที่จะสงบลง optimizer ที่ได้รับโมเดลทำนายที่ไม่เสถียร จะวางแผนบนจินตนาการ

### 2.3 Runge-Kutta 4: ตัวเลือกมาตรฐาน

วิธีแก้คือสุ่มตัวอย่างอนุพันธ์ที่หลายจุด *ภายใน* ช่วง แล้วรวมกันเพื่อให้เทอมเทย์เลอร์ตัดกันมากขึ้น วิธี Runge-Kutta อันดับสี่แบบคลาสสิกใช้สี่ตัวอย่าง:

$$\begin{aligned}
k_1 &= f(x_k,\; u_k) && \text{ความชันที่จุดเริ่มต้น}\\
k_2 &= f\big(x_k + \tfrac{\Delta t}{2}k_1,\; u_k\big) && \text{ความชันที่กึ่งกลาง โดยก้าวด้วย } k_1\\
k_3 &= f\big(x_k + \tfrac{\Delta t}{2}k_2,\; u_k\big) && \text{กึ่งกลางอีกครั้ง ปรับด้วย } k_2\\
k_4 &= f\big(x_k + \Delta t\,k_3,\; u_k\big) && \text{ความชันที่จุดสิ้นสุด}\\[4pt]
x_{k+1} &= x_k + \frac{\Delta t}{6}\big(k_1 + 2k_2 + 2k_3 + k_4\big)
\end{aligned}$$

น้ำหนัก $1,2,2,1$ หารด้วย 6 ไม่ได้มาแบบสุ่ม: มันคือค่าที่ทำให้การรวมกันตรงกับการกระจายเทย์เลอร์จริงไปจนถึงเทอม $\Delta t^4$ พอดี ผลลัพธ์คือ **ความคลาดเคลื่อนเฉพาะที่ $O(\Delta t^5)$ ความคลาดเคลื่อนรวม $O(\Delta t^4)$**

ในทางรูปธรรม การลดขนาดขั้นลงครึ่งหนึ่งลดความคลาดเคลื่อนของ Euler ลง 2 เท่า และของ RK4 ลง 16 เท่า ที่ $\Delta t = 0.1$ ความแตกต่างนั้นคือความแตกต่างระหว่างการทำนายที่ใช้ได้ กับที่ใช้ไม่ได้

สังเกตว่า $u_k$ ถูกถือไว้ **คงที่** ตลอดการประเมินทั้งสี่ครั้ง นั่นคือ zero-order hold อีกครั้ง — ถูกต้องทางกายภาพ เพราะเราส่งคำสั่งหนึ่งครั้งต่อ tick และมันคงอยู่จนถึงครั้งถัดไป

### 2.4 RK4 มีค่าใช้จ่ายเท่าไหร่

การประเมิน $f$ สี่ครั้งต่อขั้น เทียบกับหนึ่งครั้งสำหรับ Euler การประเมินแต่ละครั้งต้องสร้าง $R(\eta)$, $M(\eta)$, $W(\eta)$ และ **invert** $M(\eta)$ — ส่วนที่แพง ตลอด horizon $N$ ขั้น นั่นคือ $4N$ การประเมินต่อการ rollout พลศาสตร์หนึ่งครั้ง และ (ที่สำคัญ) ตัวแก้ต้องการไม่ใช่แค่ $f$ แต่ต้องการ *อนุพันธ์* ของมันเทียบกับ $x$ และ $u$ ที่ทุกจุดเหล่านั้น

นี่คือเหตุผลที่ส่วนที่ 10 (automatic differentiation) และส่วนที่ 11 (กลยุทธ์ real-time) มีอยู่ การประเมินพลศาสตร์ครองค่าใช้จ่ายของ nonlinear MPC

การ optimize เชิงปฏิบัติที่ควรรู้: แทนที่จะสร้าง $M(\eta)^{-1}$ อย่างชัดเจน ให้แก้ระบบเชิงเส้น $M(\eta)\,\ddot\eta = W(\eta)^T\tau_{body}$ หา $\ddot\eta$ มันเป็นระบบ $3\times3$ ดังนั้นการประหยัดจึงไม่มาก แต่การ invert อย่างชัดเจนทั้งช้ากว่าและแย่กว่าเชิงตัวเลข และนิสัยนี้สำคัญขึ้นเมื่อโมเดลใหญ่ขึ้น

### 2.5 เขียนพลศาสตร์แบบ discrete อย่างกระชับ

ไม่ว่าเราเลือก integrator ตัวไหน ผลลัพธ์คือ discrete map

$$x_{k+1} = F(x_k, u_k)$$

โดย $F$ หมายถึง "integrate $f$ จาก $x_k$ โดยถือ $u_k$ ไว้เป็นเวลา $\Delta t$" จากนี้ไปทุกอย่างใช้ $F$; การเลือก integrator ถูกห่อหุ้มอยู่ข้างใน

## ส่วนที่ 3: Transcription — เปลี่ยนวิถีเป็นตัวแปร

### 3.1 ปัญหาที่ต้องแก้

เราต้องการ optimize บน *ฟังก์ชัน* — สัญญาณควบคุมต่อเนื่อง $u(t)$ ตลอด horizon แต่คอมพิวเตอร์ optimize บนรายการตัวเลขที่จำกัด **Transcription** คือกระบวนการแปลงอย่างแรกเป็นอย่างหลัง

### 3.2 สองวิธี และทำไมการเลือกสำคัญกว่าเดิมมาก

**Single shooting** ให้เฉพาะ controls $u_0,\dots,u_{N-1}$ เป็นตัวแปรตัดสินใจ และได้ states มาจากการ roll พลศาสตร์ไปข้างหน้า: $x_1 = F(x_0,u_0)$, $x_2 = F(F(x_0,u_0),u_1)$ และต่อไปเรื่อยๆ

สำหรับโมเดล point-mass เชิงเส้น นี่แค่ไม่สวยงาม แต่สำหรับโมเดลไม่เชิงเส้น มันอันตรายจริงๆ เพราะความคลาดเคลื่อน *ทบต้นแบบคูณ* ผ่านการ rollout ความไวของ state สุดท้ายต่อ control แรกเป็นผลคูณของ Jacobian:

$$\frac{\partial x_N}{\partial u_0} = \frac{\partial F}{\partial x}\bigg|_{N-1}\frac{\partial F}{\partial x}\bigg|_{N-2}\cdots\frac{\partial F}{\partial x}\bigg|_{1}\frac{\partial F}{\partial u}\bigg|_{0}$$

สำหรับพลศาสตร์ที่ไม่เสถียรหรือเร็ว — โหมดการหมุนของเราพอดี — ผลคูณ Jacobian เหล่านี้โตแบบเอกซ์โพเนนเชียลใน $N$ optimizer จะเห็น gradient ที่ต่างกันหลาย order of magnitude ระหว่าง control ต้นๆ กับท้ายๆ และการลู่เข้าจะแย่ลงมาก นี่คือรูปแบบความล้มเหลวคลาสสิกของ single shooting บนระบบไม่เชิงเส้น

**Multiple shooting** (สิ่งที่ควรใช้) ให้ **ทั้ง** states และ controls เป็นตัวแปรตัดสินใจ และบังคับพลศาสตร์เป็นข้อจำกัดสมการอย่างชัดเจน เรียกว่าข้อจำกัด *defect*:

$$c_k(x_k,u_k,x_{k+1}) \;=\; x_{k+1} - F(x_k,u_k) \;=\; 0, \qquad k=0,\dots,N-1$$

เรียกว่า "defect" เพราะปริมาณนี้วัดช่องว่างระหว่างที่ที่พลศาสตร์บอกว่าคุณจะไปถึง กับที่ที่ตัวแปรตัดสินใจบอกว่าคุณอยู่ ที่คำตอบ defect ทั้งหมดเป็นศูนย์และวิถีสอดคล้องกันทางกายภาพ; *ระหว่าง* การแก้ พวกมันอาจไม่เป็นศูนย์ ซึ่งนั่นคือประเด็นพอดี

### 3.3 ทำไม multiple shooting ถึงชนะ

- **ไม่ทบต้น** แต่ละ defect เชื่อมโยงแค่ $x_k$, $u_k$, $x_{k+1}$ ห่วงโซ่ Jacobian ยาวถูกแยกเป็น $N$ ชิ้นสั้นๆ ที่เป็นอิสระต่อกัน
- **Sparsity** Jacobian ของข้อจำกัดเป็นแบบ block-banded พีชคณิตเชิงเส้นแบบ sparse ใช้ประโยชน์จากสิ่งนี้ได้ดีมากจนค่าใช้จ่ายสเกลแบบ *เชิงเส้น* ใน $N$ ทำให้ตัวแปรที่เพิ่มมาแทบจะฟรี
- **ข้อจำกัด state เป็นเรื่องง่าย** ขีดจำกัดการเอียง $|\phi_k|\le\phi^{max}$ เป็นแค่ขอบเขตบนตัวแปร ไม่ใช่ฟังก์ชันไม่เชิงเส้นของทุก control ก่อนหน้า
- **อนุญาตให้เริ่มต้นแบบ infeasible** — และนี่เป็นข้อได้เปรียบเชิงปฏิบัติที่สำคัญจริงๆ คุณสามารถให้ optimizer เริ่มด้วยการเดาที่ไม่สอดคล้องกับพลศาสตร์เลย (เช่น เส้นตรงจากจุดเริ่มไปเป้าหมาย) ตัวแก้จะขับ defect ให้เป็นศูนย์ขณะที่มันลู่เข้า Single shooting ทำแบบนี้ไม่ได้: states ของมันถูก *นิยาม* โดย rollout เสมอ ดังนั้นคุณเดาได้แค่ controls
- **ทำขนานได้** การประเมินพลศาสตร์ทั้ง $N$ ครั้งเป็นอิสระต่อกันและคำนวณพร้อมกันได้

### 3.4 ตัวแปรตัดสินใจ

$$z = \big(x_0, x_1, \dots, x_N,\; u_0, u_1, \dots, u_{N-1}\big)$$

ด้วย $n_x = 12$, $n_u = 4$ และ horizon $N$:

| ปริมาณ | จำนวน |
|---|---|
| States | $12(N+1)$ |
| Controls | $4N$ |
| **รวม** | $\mathbf{16N + 12}$ |

สำหรับ $N = 20$: 332 ตัวแปรตัดสินใจ (เทียบ: 186 สำหรับโมเดล point-mass ที่ horizon เดียวกัน ไม่ถึงสองเท่า — ขนาดที่เพิ่มขึ้น *ไม่ใช่* สิ่งที่ทำให้ปัญหานี้ยาก ความไม่นูน (nonconvexity) ต่างหาก)

## ส่วนที่ 4: ฟังก์ชันต้นทุน

### 4.1 รูปแบบทั่วไป

$$J = \sum_{k=0}^{N-1}\Big[\underbrace{(x_k - x_k^{ref})^TQ(x_k - x_k^{ref})}_{\text{การติดตาม state}} + \underbrace{(u_k - u_{hover})^TR(u_k - u_{hover})}_{\text{ความพยายามควบคุม}}\Big] + \underbrace{(x_N - x_N^{ref})^TQ_f(x_N-x_N^{ref})}_{\text{terminal}}$$

โดย $Q, Q_f \succeq 0$ และ $R \succ 0$ เป็นเมทริกซ์น้ำหนัก สามความละเอียดอ่อนด้านล่างเฉพาะเจาะจงกับโมเดลนี้ และผิดพลาดได้ง่าย

### 4.2 ความละเอียดอ่อนที่ 1: ความคลาดเคลื่อนของการวางตัวไม่ใช่การลบกัน

สำหรับตำแหน่ง $\xi_k - \xi_k^{ref}$ ถูกต้องเป๊ะ แต่สำหรับ **yaw** ไม่ใช่

สมมติ $\psi = +179°$ และ $\psi^{ref} = -179°$ การลบแบบตรงไปตรงมาให้ความคลาดเคลื่อน $358°$ ในขณะที่ระยะเชิงมุมจริงคือ $2°$ ในทิศทางตรงข้าม ป้อนสิ่งนั้นให้ optimizer แล้วมันจะสั่งการหมุนเต็มรอบที่รุนแรงและไม่จำเป็นเลย

Yaw อยู่บนวงกลม ไม่ใช่เส้นตรง มีวิธีแก้มาตรฐานสองแบบ:

$$e_\psi = \operatorname{atan2}\big(\sin(\psi - \psi^{ref}),\; \cos(\psi-\psi^{ref})\big)$$

ซึ่ง wrap ความคลาดเคลื่อนให้อยู่ใน $(-\pi,\pi]$ หรือทางเลือกที่ราบเรียบกว่า

$$e_\psi^2 \;\longrightarrow\; 2\big(1 - \cos(\psi - \psi^{ref})\big)$$

ซึ่งตรงกับ $e_\psi^2$ ถึงอันดับสองใกล้ศูนย์ และไม่มี branch cut เลย — มักดีกว่าเมื่ออยู่ใน optimizer เพราะ `atan2` ทำให้เกิดความไม่ต่อเนื่องของอนุพันธ์ที่ตัวแก้อาจสะดุด

Roll และ pitch ไม่ต้องการสิ่งนี้ในทางปฏิบัติ (พวกมันถูกจำกัดให้ห่างจาก $\pm\pi$ มากด้วยข้อจำกัดการเอียงในส่วนที่ 5.4) แต่ yaw ต้องการจริงๆ

### 4.3 ความละเอียดอ่อนที่ 2: ความพยายามควบคุมวัดเทียบกับ *hover* ไม่ใช่ศูนย์

ข้อนี้สำคัญมาก และถ้าทำผิดจะได้โดรนที่ไม่ยอมบิน

เทอมความพยายามควบคุมแบบไร้เดียงสา $\|u_k\|^2$ ลงโทษแรงขับโรเตอร์ในเชิงสัมบูรณ์ — ดังนั้น control ที่ถูกที่สุดคือ $u = 0$ กล่าวคือ **ปิดมอเตอร์ทั้งหมด** optimizer จะแลกความสูงกับต้นทุนควบคุมตลอดเวลา และโดรนจะร่วงลง

วิธีแก้คือลงโทษ *การเบี่ยงเบนจาก input สมดุล*: สิ่งที่มอเตอร์ต้องผลิตเพียงเพื่อ hover มาอนุพันธ์กัน ที่ hover, $\eta = 0$, $\dot\eta = 0$, $\dot\xi = 0$ ดังนั้นพลศาสตร์ต้องการ $T = mg$ และ $\tau_{body} = 0$ แทนลงในเมทริกซ์ mixer:

$$\begin{aligned}
f_1+f_2+f_3+f_4 &= mg &&\text{(แรงขับสมดุลน้ำหนัก)}\\
l(f_2 - f_4) &= 0 \;\Rightarrow\; f_2 = f_4 &&(\tau_\phi = 0)\\
l(f_3 - f_1) &= 0 \;\Rightarrow\; f_1 = f_3 &&(\tau_\theta = 0)\\
c(f_1 - f_2 + f_3 - f_4) &= 0 \;\Rightarrow\; f_1 = f_2 &&(\tau_\psi = 0,\text{ ใช้ผลข้างบน})
\end{aligned}$$

ทั้งสี่เท่ากัน รวมกันได้ $mg$:

$$\boxed{\;u_{hover} = \frac{mg}{4}\,[1,1,1,1]^T\;}$$

ดังนั้นเทอมที่ถูกต้องคือ $(u_k - u_{hover})^TR(u_k-u_{hover})$: การ hover ฟรี และลงโทษเฉพาะ *การเบี่ยงเบน* จาก hover เท่านั้น (การเขียน $(u_k-u_{hover})^TRu_k$ แบบไม่สมมาตรคือรูปที่พลาดได้ง่าย; `MPC_explanation_my_version.md` ส่วนที่ III ขั้นที่ 2 เขียนรูปสมมาตรไว้)

### 4.4 ความละเอียดอ่อนที่ 3: states มีหน่วยที่ต่างกันมาก

$Q$ ถ่วงน้ำหนักเมตรเทียบกับเรเดียน เทียบกับเมตร/วินาที เทียบกับเรเดียน/วินาที ทั้งหมดรวมเป็นสเกลาร์ตัวเดียว "1" ใน block ตำแหน่ง กับ "1" ใน block การวางตัว **ไม่ได้** หมายถึงสิ่งที่เทียบเคียงกันได้ — ความคลาดเคลื่อนตำแหน่ง 1 เมตร กับความคลาดเคลื่อนการวางตัว 1 เรเดียน (57°!) ต่างกันมหาศาลในแง่ความรุนแรง

วินัยมาตรฐานคือใช้ **กฎของ Bryson (Bryson's rule)** เป็นจุดเริ่มต้น: ตั้งน้ำหนักในแนวทแยงแต่ละตัวให้เป็นส่วนกลับของกำลังสองของการเบี่ยงเบนสูงสุดที่ยอมรับได้ในช่องนั้น

$$Q_{ii} = \frac{1}{(\text{ความคลาดเคลื่อนสูงสุดที่ยอมรับได้ของ state } i)^2}$$

เพื่อให้ทุกเทอมมีส่วนร่วมเทียบเคียงกันได้เมื่ออยู่ที่ขีดจำกัดของตัวเอง แล้วปรับจูนต่อจากนั้น ถ้าไม่มีอะไรทำนองนี้ การปรับจูนน้ำหนักก็เป็นการเดาข้ามหน่วยที่เทียบกันไม่ได้

### 4.5 Terminal cost และทำไมมันไม่ใช่ตัวเลือกเสริมที่นี่

Terminal cost $Q_f$ คือสิ่งที่หยุด optimizer จากการวางแผนวิถีที่จบลงใน state หายนะนอก horizon พอดี — เช่น ไปถึงตำแหน่งที่ถูกต้องขณะที่กลับหัวและหมุนคว้าง horizon จำกัดเห็นแค่ $N$ ขั้น; เทอม terminal คือตัวแทนของทุกอย่างหลังจากนั้น

ตัวเลือกที่ถูกหลักการคือ **infinite-horizon LQR cost-to-go**: linearize $f$ รอบจุดสมดุล hover แก้สมการ discrete algebraic Riccati

$$P = A^TPA - A^TPB(R + B^TPB)^{-1}B^TPA + Q$$

แล้วตั้ง $Q_f = P$ สิ่งนี้ทำให้ต้นทุน finite-horizon ประมาณค่าต้นทุน infinite-horizon และ (ร่วมกับ terminal constraint set) เป็นเส้นทางมาตรฐานสู่ **การรับประกันเสถียรภาพ closed-loop ที่พิสูจน์ได้** สำหรับตัวควบคุม MPC

สิ่งนี้สำคัญกว่ามากสำหรับโมเดลไม่เชิงเส้นเทียบกับ point mass point mass ที่มี terminal cost แย่จะติดตามแย่ลงเล็กน้อย; quadrotor ที่ underactuated ที่มี terminal cost แย่สามารถวางแผนตัวเองเข้าสู่การวางตัวที่กู้คืนไม่ได้

## ส่วนที่ 5: ข้อจำกัด

### 5.1 เงื่อนไขเริ่มต้น

$$x_0 = \hat x(t)$$

state ที่วัดได้ (หรือประมาณได้) เช่นเคย นี่คือบรรทัดเดียวที่ทำให้ทั้งระบบเป็นตัวควบคุมแบบป้อนกลับ แทนที่จะเป็นการวางแผนแบบ open-loop

สังเกตว่า $\hat x$ ตอนนี้รวม **การวางตัวและความเร็วเชิงมุม** ไม่ใช่แค่ตำแหน่งกับความเร็ว — 12 ตัวเลขที่ต้องมาจาก estimator นี่เป็นความต้องการด้านการรับรู้ที่หนักกว่าเวอร์ชัน point-mass อย่างมีนัยสำคัญ และเป็นจุดที่ state estimator (งาน Kalman filter ในรายการโปรเจกต์) กลายเป็นสิ่งที่รับน้ำหนักจริงๆ ไม่ใช่แค่ของดีที่มีก็ดี

### 5.2 Dynamics defects

$$x_{k+1} - F(x_k,u_k) = 0, \qquad k = 0,\dots,N-1$$

$12N$ ข้อจำกัดสมการสเกลาร์ ต่างจากกรณี point-mass สิ่งเหล่านี้ **ไม่เชิงเส้น** และข้อเท็จจริงเดียวนั้นคือสิ่งที่เปลี่ยนคลาสของปัญหาในส่วนที่ 6

### 5.3 ขอบเขตแรงขับโรเตอร์

$$0 \;\le\; f_{i,k} \;\le\; f_{max}, \qquad i = 1,\dots,4$$

ขอบล่างเป็นเรื่องกายภาพจริงๆ ไม่ใช่ความระมัดระวังเกินเหตุ: โรเตอร์ pitch คงที่ผลักได้ แต่ **ดึงไม่ได้** ขอบบนคือค่าสูงสุดของมอเตอร์

นี่คือเหตุผลพอดีที่ควรกำหนดปัญหาในรูปแรงของโรเตอร์แต่ละตัว $f_i$ แทน $(T, \tau_{body})$ ในพิกัด $(T,\tau)$ "โรเตอร์แต่ละตัวอยู่ในขีดจำกัดของมัน" แปลงเป็น polytope ที่ยุ่งยาก; ในพิกัด $f_i$ มันคือสี่ขอบเขตธรรมดา ฟิสิกส์เดียวกัน แต่มีเงื่อนไขที่ดีกว่ามาก

$8N$ อสมการสเกลาร์

### 5.4 ขีดจำกัดการเอียง

$$|\phi_k| \le \phi^{max}, \qquad |\theta_k| \le \theta^{max}$$

มีเหตุผลอิสระสองข้อที่ต้องใส่สิ่งนี้ และควรแยกออกจากกัน:

1. **ทางกายภาพ** เกินประมาณ 60° ของการเอียง องค์ประกอบแรงขับแนวดิ่ง $T\cos\phi\cos\theta$ ไม่สามารถรองรับน้ำหนักของยานได้อีกต่อไป และมันจะสูญเสียความสูงไม่ว่าจะเร่งเท่าไหร่
2. **ทางคณิตศาสตร์** $W(\eta)$ กลายเป็น singular ที่ $\theta = \pm 90°$ — gimbal lock ซึ่งกางไว้ใน [`euler_angle_rates.md`](euler_angle_rates.md#gimbal-lock) — ซึ่งจะทำให้ $M(\eta)^{-1}$ ระเบิดภายในฟังก์ชันพลศาสตร์ของเราเอง การจำกัดการเอียงไว้ที่ เช่น $\pm45°$ ทำให้ iterate ของ optimizer อยู่ห่างจากบริเวณที่ *การแทนค่า* ที่เราเลือกพังลง โดยไม่เกี่ยวว่ายานจริงจะรอดหรือไม่

เหตุผลข้อ 2 มองข้ามได้ง่ายและสำคัญ: ข้อจำกัดนี้ปกป้องตัวแก้จากทางเลือกการสร้างโมเดลของเราบางส่วน ไม่ใช่แค่ปกป้องโดรน

## ส่วนที่ 6: ตอนนี้มันเป็นปัญหาชนิดไหน

### 6.1 NLP ที่ไม่นูน (nonconvex)

วัตถุประสงค์เป็นกำลังสอง แต่ **ข้อจำกัดสมการไม่เชิงเส้น** (defects) นั่นทำให้นี่เป็น **Nonlinear Program (NLP)** ทั่วไป — และเพราะสมการไม่เชิงเส้นนิยามเซตที่เป็นไปได้ที่โค้งและไม่นูน มันจึง **ไม่นูน (nonconvex)**

นี่คือความแตกต่างที่มีผลมากที่สุดจากตัวควบคุม point-mass ดังนั้นควรทำตารางว่าอะไรหายไปบ้าง:

| | Point-mass (convex QP) | โมเดลเต็ม (nonconvex NLP) |
|---|---|---|
| Local optimum ⇒ global | **ใช่** | **ไม่** |
| คำตอบไม่ซ้ำ (unique) | ใช่ | ไม่ |
| ตรวจจับ feasibility ได้ | เชื่อถือได้ | ยาก |
| เวลาในการแก้ | คาดเดาได้ | ผันแปร |
| ค่าเดาเริ่มต้น | ไม่เกี่ยว | **สำคัญมาก** |
| จำนวน iteration | น้อย สม่ำเสมอ | ผันแปร ล้มเหลวได้ |

ทุกการรับประกันในคอลัมน์ซ้ายหายไปหมด ตรีโกณมิติที่เพิ่มมาเป็นเรื่องรอง; *สิ่งนี้* ต่างหากคือต้นทุนจริงของโมเดลที่ดีกว่า

### 6.2 local minimum หน้าตาเป็นอย่างไรทางกายภาพ

ความไม่นูนไม่ใช่เรื่องนามธรรมที่นี่ ตัวอย่างรูปธรรม: โดรนต้อง yaw 180° การหมุนซ้ายกับหมุนขวาต่างก็เป็น local optimum ทั้งคู่ แยกกันด้วยกำแพงต้นทุน ตัวแก้ที่เริ่มด้วยการเดาไปทางซ้ายจะลู่เข้าซ้าย และไม่มีวันค้นพบว่าขวาก็ดีเท่ากัน — หรือเมื่อมีสิ่งกีดขวางที่ไม่สมมาตร ขวาอาจ *ดีกว่า*

อีกตัวอย่าง: เพื่อไปถึงตำแหน่งอย่างรวดเร็ว optimizer อาจพบคำตอบที่เอียงอย่างรุนแรงไปทางหนึ่ง และอีกคำตอบที่เอียงไปอีกทาง โดยมีบริเวณต้นทุนแย่กว่าอยู่ระหว่างกลาง คุณจะได้อันไหนขึ้นอยู่กับว่าคุณเริ่มจากที่ไหนล้วนๆ

### 6.3 ทำไม warm starting ตอนนี้จึงจำเป็น ไม่ใช่แค่ช่วยให้ดีขึ้น

ในกรณีนูน warm starting เป็นการ optimize ประสิทธิภาพ — ตัวแก้จะพบ global optimum ตัวเดียวกันไม่ว่าจะเริ่มจากไหน

ที่นี่ ค่าเดาเริ่มต้น **เลือกว่าคุณจะลู่เข้า local optimum อันไหน** ดังนั้นการ warm start จากคำตอบของ tick ก่อนหน้าจึงทำงานจริงมากกว่าแค่ประหยัด iteration: มันทำให้ตัวควบคุมอยู่ใน *basin of attraction เดียวกัน* จาก tick หนึ่งไปอีก tick หนึ่ง ถ้าไม่มีมัน การแก้ที่ต่อเนื่องกันอาจกระโดดไปมาระหว่าง local optima คนละอัน ทำให้เกิดคำสั่งที่ไม่ต่อเนื่องอย่างรุนแรง แม้ว่าการแก้แต่ละครั้งจะ "optimal" ก็ตาม

นี่คือข้อพิจารณาด้านความปลอดภัยจริงๆ ใน nonlinear MPC ไม่ใช่เชิงอรรถด้านประสิทธิภาพ

## ส่วนที่ 7: เงื่อนไขความเหมาะสมที่สุดสำหรับ NLP

### 7.1 ลากรองเจียนและเงื่อนไข KKT

เขียนปัญหาแบบทั่วไปโดยให้ $z$ ซ้อนตัวแปรตัดสินใจทั้งหมด:

$$\min_z f(z) \quad\text{s.t.}\quad g(z) = 0,\quad h(z)\le 0$$

สร้างลากรองเจียน พับข้อจำกัดเข้าไปในวัตถุประสงค์ด้วยตัวคูณหนึ่งตัวต่อข้อจำกัด:

$$\mathcal{L}(z,\lambda,\nu) = f(z) + \lambda^Tg(z) + \nu^Th(z)$$

เงื่อนไข **Karush-Kuhn-Tucker**:

$$\begin{aligned}
&\text{Stationarity:} && \nabla f(z) + \nabla g(z)^T\lambda + \nabla h(z)^T\nu = 0\\
&\text{Primal feasibility:} && g(z)=0,\quad h(z)\le 0\\
&\text{Dual feasibility:} && \nu \ge 0\\
&\text{Complementary slackness:} && \nu_i h_i(z) = 0\ \ \forall i
\end{aligned}$$

การตีความ: ที่จุด optimum gradient ของต้นทุนถูกหักล้างพอดีด้วย gradient ของข้อจำกัด (ไม่มีอะไรดีขึ้นได้โดยไม่ละเมิดบางอย่าง); ตัวคูณตั้งราคาข้อจำกัดแต่ละตัว — optimum จะดีขึ้นเท่าไหร่ต่อการผ่อนคลายหนึ่งหน่วย; และแต่ละอสมการไม่ inactive โดยมีราคาเป็นศูนย์ ก็ active และอยู่บนขอบเขตพอดี

### 7.2 ความแตกต่างสำคัญจากกรณีนูน

สำหรับ convex QP, KKT เป็นทั้ง **จำเป็นและเพียงพอ**: หาจุด KKT เจอ แล้วคุณได้พิสูจน์ว่าพบ global optimum แล้ว

ที่นี่ KKT เป็นเพียง **จำเป็น** เท่านั้น จุด KKT อาจเป็น local minimum, saddle point หรือแม้แต่ local maximum เพื่อยืนยันว่าเป็น local *minimum* คุณต้องใช้เงื่อนไขอันดับสอง: Hessian ของลากรองเจียนต้องเป็นบวกแน่นอนบน null space ของ gradient ของข้อจำกัดที่ active

$$d^T\nabla^2_{zz}\mathcal{L}\,d > 0 \quad \text{สำหรับทุก } d\neq 0 \text{ ที่ } \nabla g\,d = 0,\ \nabla h_{\mathcal{A}}d = 0$$

("การเคลื่อนไปในทิศทางใดก็ตามที่ยังคง feasible จะเพิ่มต้นทุน") และแม้แต่สิ่งนี้ก็รับรองได้แค่ local minimum เท่านั้น — โดยทั่วไป global optimality ไม่สามารถตรวจสอบได้

ยังมีข้อกำหนดทางเทคนิคอีกข้อ: เงื่อนไข KKT ใช้ได้ภายใต้ **constraint qualification** เช่น LICQ (gradient ของข้อจำกัดที่ active ต้องเป็นอิสระเชิงเส้น) เท่านั้น โดยปกติสิ่งนี้เป็นจริง แต่มันล้มเหลวได้เมื่อมีข้อจำกัดซ้ำซ้อนหรือเสื่อม — อีกเหตุผลที่ควรเลือกการกำหนดข้อจำกัดที่สะอาดไม่ซ้ำซ้อน อย่างขอบเขตแรงขับโรเตอร์ในส่วนที่ 5.3

## ส่วนที่ 8: วิธีแบบ Newton

### 8.1 แนวคิดหลัก

เงื่อนไข KKT คือระบบสมการไม่เชิงเส้น (บวกอสมการ) วิธีของนิวตันเป็นเครื่องมือธรรมชาติ: linearize, แก้หาก้าว, เคลื่อนที่, ทำซ้ำ ถ้าละเว้นอสมการไว้ก่อน เราต้องการ $F(z,\lambda)=0$ โดย

$$F(z,\lambda) = \begin{bmatrix}\nabla f(z) + \nabla g(z)^T\lambda\\ g(z)\end{bmatrix}$$

ก้าวของนิวตันแก้ $\nabla F\cdot\Delta = -F$ ซึ่งเขียนออกมาคือ **ระบบ KKT**:

$$\begin{bmatrix}
W & \nabla g^T\\
\nabla g & 0
\end{bmatrix}
\begin{bmatrix}\Delta z\\ \Delta\lambda\end{bmatrix}
= -\begin{bmatrix}\nabla_z\mathcal{L}\\ g(z)\end{bmatrix},
\qquad W = \nabla^2_{zz}\mathcal{L}$$

### 8.2 Hessian ไม่คงที่อีกต่อไป — และอาจไม่แน่นอน (indefinite)

สำหรับ point-mass QP, $W$ คือ Hessian ของต้นทุนที่คงที่: ข้อจำกัดเป็นเชิงเส้น ดังนั้นอนุพันธ์อันดับสองของพวกมันหายไปและไม่มีส่วนร่วมเลย

ที่นี่ไม่ใช่แบบนั้น เพราะ $g$ ไม่เชิงเส้น Hessian ของลากรองเจียนจึงรับความโค้งจากตัวข้อจำกัดเอง ถ่วงน้ำหนักด้วยตัวคูณของพวกมัน:

$$W = \nabla^2 f(z) + \sum_i \lambda_i\nabla^2 g_i(z) + \sum_j \nu_j\nabla^2 h_j(z)$$

ผลสองประการ:

1. **$W$ เปลี่ยนทุก iteration** และต้องคำนวณใหม่ — อนุพันธ์อันดับสองของพลศาสตร์ ซึ่งแพง
2. **$W$ อาจ indefinite** เทอม $\lambda_i\nabla^2g_i$ ไม่มีการรับประกันเครื่องหมาย ถ้า $W$ indefinite ทิศทางของนิวตันอาจไม่ใช่ทิศทางลง (descent direction) เลย — มันชี้ขึ้นเนินได้

ตัวแก้จัดการข้อ (2) ด้วย **regularization**: เพิ่ม $\delta I$ เข้าไปใน block ของ Hessian เพิ่ม $\delta$ จนกว่าเมทริกซ์ KKT จะมี *inertia* ที่ถูกต้อง ($n$ ค่าเจาะจงบวก และ $m$ ค่าเจาะจงลบ ซึ่งเป็นลายเซ็นของ minimum ที่แท้จริง) IPOPT ทำสิ่งนี้พอดีโดยอัตโนมัติ มันมีค่าใช้จ่ายเป็นการ factorize เพิ่มเมื่อถูกกระตุ้น — เป็นแหล่งซ่อนเร้นของเวลาแก้ปัญหาที่ผันแปร

### 8.3 Hessian ที่ถูกกว่า: Gauss-Newton

เพราะต้นทุนของเราเป็น **ผลรวมของกำลังสอง** — เขียนเป็น $f(z) = \tfrac12\|r(z)\|^2$ โดย residual $r$ รวบรวมความคลาดเคลื่อนการติดตามที่ถ่วงน้ำหนักทั้งหมด — Hessian ที่แน่นอนคือ

$$\nabla^2 f = J_r^TJ_r + \sum_i r_i\nabla^2 r_i, \qquad J_r = \frac{\partial r}{\partial z}$$

**การประมาณแบบ Gauss-Newton** ทิ้งเทอมที่สอง:

$$\nabla^2 f \;\approx\; J_r^TJ_r$$

สามเหตุผลที่นี่เป็นวิธีมาตรฐานใน NMPC สำหรับการติดตาม:

- **เป็น positive semidefinite เสมอ** โดยการสร้าง ดังนั้นทิศทางเป็น descent direction เสมอ — ไม่ต้อง regularize ไม่มี indefiniteness
- **ต้องการแค่อนุพันธ์อันดับหนึ่ง** ไม่ต้องใช้อนุพันธ์อันดับสองของพลศาสตร์เลย: ประหยัดมาก เพราะพวกนั้นเป็นปริมาณที่แพงที่สุด
- **เทอมที่ทิ้งไปมีค่าน้อยเมื่อติดตามได้ดี** เพราะมันถ่วงน้ำหนักด้วยตัว residual $r_i$ เอง — และในตัวควบคุมที่ทำงานได้ดี residual *มีค่าน้อย*

ต้นทุนคืออัตราการลู่เข้า: superlinear แทนที่จะเป็น quadratic แบบนิวตัน สำหรับ NMPC แบบ real-time การแลกเปลี่ยนนั้นแทบจะคุ้มเสมอ และ Gauss-Newton คือสิ่งที่ `acados` ใช้เป็นค่าเริ่มต้น

(ตัวเลือกกลางๆ คือ **BFGS** ซึ่งสร้างการประมาณ Hessian แบบ PSD จาก gradient ที่ต่อเนื่องกัน มันพบได้ทั่วไปใน optimization ทั่วไป — IPOPT รองรับผ่าน `hessian_approximation: limited-memory` — แต่สำหรับปัญหาการติดตามแบบ least-squares Gauss-Newton ใช้ประโยชน์จากโครงสร้างได้ดีกว่า)

## ส่วนที่ 9: ตัวแก้สองตระกูล

### 9.1 Sequential Quadratic Programming (SQP)

**แนวคิด:** ประมาณ NLP ด้วย QP ที่ iterate ปัจจุบัน แก้ QP นั้นให้แน่นอน ก้าว แล้วทำซ้ำ ที่ iterate $z^{(i)}$:

$$\begin{aligned}
\min_{\Delta z}\quad & \tfrac12\Delta z^TW\Delta z + \nabla f(z^{(i)})^T\Delta z\\
\text{s.t.}\quad & g(z^{(i)}) + \nabla g(z^{(i)})\Delta z = 0\\
& h(z^{(i)}) + \nabla h(z^{(i)})\Delta z \le 0
\end{aligned}$$

ข้อจำกัดถูก *linearize*; วัตถุประสงค์เป็นโมเดลกำลังสอง สังเกตว่าปัญหาย่อย QP นี้มีโครงสร้างเหมือนปัญหา point-mass จากเอกสารอีกฉบับพอดี — ดังนั้นกลไกทั้งหมดสำหรับแก้ convex QP ใช้ได้โดยตรงในทุก iteration

จุดแข็ง: warm starting ที่ยอดเยี่ยม (active set เปลี่ยนน้อยระหว่าง tick); เร็วมากเมื่อเริ่มใกล้คำตอบ — ซึ่งเป็นสถานการณ์ปกติของ MPC นี่คือสิ่งที่ทำให้ SQP เป็นตัวเลือกหลักสำหรับ NMPC แบบ real-time

### 9.2 Interior-point (IPOPT)

**แนวคิด:** กำจัดความยากเชิงการจัดหมู่ของ "อสมการไหน active" โดยแทนที่มันด้วย barrier แบบลอการิทึมที่กลายเป็นอนันต์ที่ขอบเขต:

$$\min_z\; f(z) - \mu\sum_i\log\big(-h_i(z)\big)\quad\text{s.t.}\quad g(z)=0$$

การอนุพันธ์ว่าสิ่งนี้ทำอะไรกับเงื่อนไข KKT ให้ความกระจ่างมาก ให้ $s_i \equiv -h_i(z) > 0$ (slack — ระยะห่างถึงข้อจำกัด $i$) แล้ว

$$\frac{\partial}{\partial z}\big[-\mu\log s_i\big] = -\frac{\mu}{s_i}\cdot(-\nabla h_i) = \frac{\mu}{s_i}\nabla h_i$$

ดังนั้นเงื่อนไข stationarity ของปัญหา barrier คือ

$$\nabla f + \nabla g^T\lambda + \sum_i\frac{\mu}{s_i}\nabla h_i = 0$$

เทียบกับเงื่อนไข stationarity จริงในส่วนที่ 7.1 สิ่งเหล่านี้ *เหมือนกันทุกประการ* ถ้าเรานิยาม $\nu_i \equiv \mu/s_i$ กล่าวคือ

$$\nu_i s_i = \mu$$

นั่นคือผลลัพธ์เชิงโครงสร้างที่สำคัญ: **ปัญหา barrier สอดคล้องกับเงื่อนไข KKT ที่แท้จริงทุกประการ ยกเว้น complementary slackness ถูกรบกวนจาก $\nu_is_i = 0$ เป็น $\nu_is_i = \mu$** เงื่อนไขแบบ "อย่างใดอย่างหนึ่ง" ที่ยุ่งยากกลายเป็นสมการที่ราบเรียบ ตระกูลของคำตอบที่ลากออกมาเมื่อ $\mu$ เปลี่ยนเรียกว่า **central path** และอัลกอริทึมคือ: แก้สำหรับ $\mu$ หนึ่งค่า ลด $\mu$ ทำซ้ำจนกระทั่ง $\mu\to0$ กู้คืน complementarity ที่แท้จริง

แต่ละ iteration ภายในคือก้าวของนิวตันบนระบบที่ถูกรบกวน ให้ระบบ KKT แบบขยาย

$$\begin{bmatrix}W + \Sigma & \nabla g^T\\ \nabla g & 0\end{bmatrix}
\begin{bmatrix}\Delta z\\\Delta\lambda\end{bmatrix} = -\begin{bmatrix}r_{dual}\\ r_{primal}\end{bmatrix},
\qquad \Sigma = \mathrm{diag}(\nu_i/s_i)$$

เมื่อ iterate เข้าใกล้ขอบเขต $s_i\to0$ entry นั้นของ $\Sigma$ ระเบิด และก้าวถูกป้องกันไม่ให้ข้าม — กลไกที่บังคับความเป็น interior อย่างเคร่งครัด

Globalization ใช้ **filter line search**: แทนที่จะเรียกร้องให้วัตถุประสงค์ลดลงทุกก้าว (เข้มงวดเกินไปเมื่อต้องทำให้ข้อจำกัดสอดคล้องด้วย) IPOPT ติดตามทั้งค่าวัตถุประสงค์และการละเมิดข้อจำกัด และยอมรับก้าวที่ปรับปรุงอย่างใดอย่างหนึ่งโดยไม่ถูกครอบงำโดยคู่ที่บันทึกไว้ก่อนหน้า

### 9.3 ควรใช้อันไหน

| | SQP | Interior point |
|---|---|---|
| Warm start | **ยอดเยี่ยม** | จำกัด |
| ค่าใช้จ่ายต่อ iteration | สูงกว่า (แก้ QP) | ต่ำกว่า |
| จำนวน iteration เมื่อ warm-start | **น้อยมาก** | ปานกลาง |
| จัดการอสมการจำนวนมาก | ไม่ค่อยดี | **ดี** |
| ความเหมาะกับ NMPC แบบ real-time | **ตัวเลือกมาตรฐาน** | พบน้อยกว่า |

แถวที่ชี้ขาดคือ warm starting วิธี interior-point ต้องให้ iterate อยู่ *ภายใน* บริเวณ feasible อย่างเคร่งครัด ดังนั้น warm start ที่อยู่บนขอบเขตข้อจำกัดพอดี — ซึ่งคำตอบ optimal มักจะเป็นแบบนั้น — ต้องถูกผลักกลับเข้าข้างในก่อน ทิ้งประโยชน์ไปมาก SQP ไม่มีข้อจำกัดนั้นและใช้ active set เดิมซ้ำได้โดยตรง

สำหรับ loop ของ MPC ที่ปัญหาต่อเนื่องกันแทบเหมือนกัน ข้อได้เปรียบนั้นชี้ขาด นี่คือเหตุผลรูปธรรมที่ควรเลือก `acados` มากกว่า IPOPT สำหรับตัวควบคุมแบบ real-dynamics

## ส่วนที่ 10: อนุพันธ์มาจากไหน

ทุกวิธีข้างบนต้องการ $\nabla f$, $\nabla g$ และบ่อยครั้ง $W$ สำหรับพลศาสตร์ของเรา — RK4 ห่อรอบฟังก์ชันที่มี $R(\eta)$, $M(\eta)^{-1}$, $W(\eta)$ — การอนุพันธ์สิ่งเหล่านี้ด้วยมือเป็นไปไม่ได้

**Finite differences** ($\partial f/\partial x_i \approx [f(x+\epsilon e_i)-f(x)]/\epsilon$) เป็นทางเลือกสำรองที่ชัดเจนและแย่: ต้องประเมินฟังก์ชัน $n+1$ ครั้งต่อ Jacobian หนึ่งตัว และมีการแลกเปลี่ยนความแม่นยำที่หลีกเลี่ยงไม่ได้ ($\epsilon$ ใหญ่เกินไปให้ความคลาดเคลื่อนจากการตัดทอน เล็กเกินไปให้ catastrophic cancellation ใน floating point)

**Automatic differentiation (AD)** — สิ่งที่ CasADi ให้ — คือเครื่องมือที่ถูกต้อง AD แยกฟังก์ชันออกเป็นการดำเนินการพื้นฐานและใช้กฎลูกโซ่อย่างเป็นกลไก ให้อนุพันธ์ที่แม่นยำระดับ machine precision โดยไม่มีพารามิเตอร์ขนาดก้าว มีสองโหมด:

- **Forward mode:** ส่ง $\partial(\cdot)/\partial x_i$ ไปข้างหน้าผ่าน graph ค่าใช้จ่าย $\propto$ จำนวน *inputs*
- **Reverse mode** (backpropagation): ส่งความไวย้อนกลับจาก outputs ค่าใช้จ่าย $\propto$ จำนวน *outputs*

สำหรับ gradient (output สเกลาร์หนึ่งตัว, inputs หลายร้อยตัว) reverse mode คำนวณ gradient **ทั้งหมด** ด้วยค่าใช้จ่ายประมาณเท่ากับการประเมินฟังก์ชันหนึ่งครั้ง — ไม่ว่ามิติจะเป็นเท่าไหร่ นั่นคือความแตกต่างระหว่างทำได้กับทำไม่ได้

CasADi ยังตรวจจับ **รูปแบบ sparsity** โดยอัตโนมัติ ดังนั้นโครงสร้าง block-banded ที่สร้างโดย multiple shooting ถูกใช้ประโยชน์โดยไม่ต้องบอก และสามารถ **สร้างโค้ด C** สำหรับการประเมินทั้งหมด — กำจัด overhead ของ Python interpreter ทั้งหมด ซึ่งสำคัญมากใน loop แบบ real-time

## ส่วนที่ 11: ทำให้เป็น real-time

### 11.1 ปัญหาเรื่องงบเวลา

MPC ระดับ guidance ที่ 10 Hz ให้เวลา 100 ms ต่อการแก้ — สบาย แต่แรงจูงใจทั้งหมดของโมเดล full-dynamics คือการควบคุม *attitude* และ loop ของ attitude ต้องการ 50-250 Hz: **4-20 ms ต่อการแก้** รวมการประเมินพลศาสตร์ อนุพันธ์ และ Newton iteration หลายรอบ การทำให้ NLP ลู่เข้าเต็มที่ในหน้าต่างนั้นโดยทั่วไปเป็นไปไม่ได้

### 11.2 Real-Time Iteration (RTI) scheme

ข้อคิดสำคัญ (Diehl และคณะ) คือ **การลู่เข้าเต็มที่ไม่จำเป็น** ปัญหา MPC ที่ต่อเนื่องกันต่างกันเพียงเล็กน้อย ดังนั้นแทนที่จะ iterate จนลู่เข้าในแต่ละปัญหา ให้ทำ **SQP iteration เพียงหนึ่งครั้งต่อ control tick** โดย warm-start จากครั้งก่อน optimizer ไม่เคยลู่เข้าเต็มที่ในปัญหาเดี่ยวใดเลย — แทนที่จะเป็นแบบนั้น มัน *ติดตาม* คำตอบที่เคลื่อนที่ข้าม tick ซึ่งเป็นทั้งหมดที่ตัวควบคุมต้องการจริงๆ

RTI แบ่งแต่ละ tick เป็นสองเฟส:

- **Preparation phase** (ส่วนที่แพง): ประเมินพลศาสตร์ คำนวณ Jacobian สร้างและ condense QP ที่สำคัญคือ สิ่งนี้ขึ้นอยู่กับคำตอบ *ก่อนหน้า* เท่านั้น — ดังนั้นมันรันได้ **ก่อนที่การวัดใหม่จะมาถึง**
- **Feedback phase** (ถูก): แทน $\hat x(t)$ ใหม่ และแก้ QP ที่เตรียมไว้แล้ว

เพราะมีแค่ feedback phase ที่อยู่ระหว่างการวัดกับคำสั่ง latency ของการควบคุมที่แท้จริงจึงลดลงเหลือเศษเสี้ยวของการคำนวณทั้งหมด — มักเป็นระดับไมโครวินาที นี่คือกลเม็ดหลักที่ทำให้ nonlinear MPC เป็นไปได้บนฮาร์ดแวร์การบินจริง

### 11.3 Condensing

QP แบบ multiple-shooting มีโครงสร้าง block-banded ที่จัดการได้สองทาง:

- **Condensing:** กำจัดตัวแปร state โดยใช้พลศาสตร์ที่ linearize แล้ว เหลือ QP หนาแน่นที่เล็กกว่าในรูป controls เท่านั้น ($4N$ ตัวแปรแทน $16N+12$) ดีกว่าเมื่อ $N$ เล็ก
- **Sparse (ใช้ประโยชน์จากโครงสร้าง):** เก็บตัวแปรทั้งหมดไว้และใช้ตัวแก้ที่ออกแบบมาสำหรับระบบ KKT แบบ banded (เช่น HPIPM หรือ Riccati recursion ซึ่งสเกลเชิงเส้นใน $N$) ดีกว่าเมื่อ $N$ ใหญ่

จุดตัดมักอยู่ราว $N \approx 20{-}50$ — ตรงกับความยาว horizon ของเราพอดี ดังนั้นควร benchmark ทั้งสองแบบแทนที่จะสมมติเอา

### 11.4 acados

`acados` รวมทุกอย่างข้างบน: โค้ด C ที่สร้างขึ้น, RTI, Gauss-Newton Hessian, HPIPM เป็นตัวแก้ QP, ตัวเลือก condensing พร้อม Python interface ที่รับโมเดล CasADi ได้โดยตรง เวลาแก้ที่รายงานสำหรับ NMPC ขนาด quadrotor อยู่ในระดับหลายสิบถึงหลายร้อย **ไมโครวินาที** — เร็วกว่า IPOPT-ใน-Python-loop หลาย order of magnitude

เส้นทางการย้ายจากโค้ดปัจจุบันของเราราบรื่นผิดปกติ: นิพจน์โมเดล CasADi ใช้ซ้ำได้เลย และเปลี่ยนแค่การตั้งค่าตัวแก้เท่านั้น

## ส่วนที่ 12: สิ่งที่ควรสร้างจริงๆ

ลำดับเชิงปฏิบัติ เรียงจากความเสี่ยงต่ำสุดก่อน:

1. **เขียน $f(x,u)$ ใน CasADi** ตามที่อนุพันธ์ไว้ใน `MPC_explanation_my_version.md` ส่วนที่ I ขั้นที่ 7 พอดี โดย $\tau_{body} = \Gamma u$ จาก mixer ตรวจสอบมันแบบแยกเดี่ยวก่อนทำ optimization ใดๆ: เช็คว่า $u = u_{hover}$ ที่ $\eta = 0$ ให้ $\dot x \approx 0$ และแรงบิด roll เล็กน้อยให้ความเร่ง roll ที่มีเครื่องหมายและขนาดตามที่คาด ความผิดพลาดเรื่องเครื่องหมายในพลศาสตร์เป็นรูปแบบความล้มเหลวที่พบบ่อยที่สุดและสับสนที่สุด; จับมันตรงนี้ ไม่ใช่ในตัวแก้
2. **ห่อมันด้วย RK4** และจำลองแบบ open-loop จาก hover โมเดลที่ถูกต้องควรอยู่ใกล้ hover ชั่วครู่แล้วค่อยลอยออก — quadrotor ไม่เสถียรแบบ open-loop ในเชิง attitude ดังนั้นการลู่ออก *บางส่วน* เป็นสิ่งที่คาดหวังและถูกต้อง การลู่ออกภายในไม่กี่ timestep บ่งชี้ว่ามี bug
3. **สร้าง NLP ด้วย IPOPT ก่อน** ไม่ใช่เพราะมันเป็นตัวเลือกที่ถูกต้องระยะยาว แต่เพราะมันติดตั้งไว้แล้ว ทนทาน และผ่อนปรนขณะที่การกำหนดปัญหายังอยู่ระหว่าง debug ทดสอบแบบ offline ไม่ใช่ใน control loop
4. **ตรวจเวลาแก้อย่างตรงไปตรงมา** ถ้ามันเกิน control period ตัวควบคุมก็รันไม่ได้ — และนั่นเป็นสิ่งที่คาดหวังในขั้นนี้; มันคือข้อมูล ไม่ใช่ความล้มเหลว
5. **ย้ายไปใช้ `acados` พร้อม RTI** เมื่อยืนยันแล้วว่าการกำหนดปัญหาถูกต้อง การ optimize ก่อนที่โมเดลจะถูกต้อง คือการ optimize สิ่งที่ผิด
6. **เปลี่ยน PX4 interface เป็นอันสุดท้าย** ตัวควบคุมนี้สั่ง attitude หรือ body rates ไม่ใช่ `TrajectorySetpoint` — ดังนั้น `OffboardControlMode.body_rate` (หรือ `.attitude`) กับ `VehicleRatesSetpoint`/`VehicleAttitudeSetpoint` จะแทนที่เส้นทางปัจจุบัน ทำสิ่งนี้เมื่อตัวแก้น่าเชื่อถือแล้วเท่านั้น; การ debug ตัวควบคุมใหม่ *และ* PX4 interface ใหม่พร้อมกันคือวิธีที่โปรเจกต์เสียเวลาหลายวัน

ข้อที่ต่อรองไม่ได้ข้อเดียว: **อย่าใส่ตัวแก้ไม่เชิงเส้นที่ยังไม่ได้ตรวจสอบเข้าไปใน control loop** ขั้นที่ 1-4 เป็น offline ทั้งหมดด้วยเหตุผลนั้นพอดี

## สรุป

- โมเดลจาก `MPC_explanation_my_version.md` ไม่เชิงเส้น เชื่อมโยงกัน และ underactuated คุณสมบัติสามข้อนั้นขับเคลื่อนทุกอย่างที่นี่ (ส่วนที่ 1)
- **การ discretize ต้องทำเชิงตัวเลข** — ไม่มีรูปปิด RK4 ให้ความคลาดเคลื่อนรวม $O(\Delta t^4)$ ด้วยการประเมินพลศาสตร์ 4 ครั้งต่อขั้น; $O(\Delta t)$ ของ Euler ไม่พอและอาจไม่เสถียรบนโหมดการหมุนที่เร็ว (ส่วนที่ 2)
- **Multiple shooting** ตอนนี้จำเป็น ไม่ใช่แค่ดีกว่า: single shooting ทบ Jacobian แบบคูณตลอด horizon และมีเงื่อนไขแย่บนพลศาสตร์ไม่เชิงเส้น (ส่วนที่ 3)
- การออกแบบต้นทุนมีกับดักเฉพาะโมเดลสามข้อ: **ต้อง wrap ความคลาดเคลื่อน yaw**, **ความพยายามควบคุมต้องวัดเทียบกับ $u_{hover} = \frac{mg}{4}[1,1,1,1]^T$** (มิฉะนั้น optimizer จะชอบปิดมอเตอร์) และ **น้ำหนักครอบคลุมหน่วยที่เทียบกันไม่ได้** ดังนั้นต้องมีอะไรทำนองกฎของ Bryson (ส่วนที่ 4)
- **ข้อจำกัดการเอียงทำหน้าที่สองอย่าง**: ทางกายภาพ (แรงขับรองรับน้ำหนักไม่ได้เกิน ~60°) และทางคณิตศาสตร์ (ทำให้ iterate อยู่ห่างจาก singularity แบบ gimbal-lock ของ $W(\eta)$) (ส่วนที่ 5.4)
- ปัญหาเป็น **nonconvex NLP** ทุกการรับประกันที่ point-mass QP ให้ — global optimality, uniqueness, เวลาแก้ที่คาดเดาได้, ความเป็นอิสระจากค่าเดาเริ่มต้น — หายไปหมด warm starting กลายเป็นเรื่องความถูกต้อง ไม่ใช่ประสิทธิภาพ เพราะค่าเดาเริ่มต้นเลือก local optimum (ส่วนที่ 6)
- **เงื่อนไข KKT ตอนนี้เป็นแค่เงื่อนไขจำเป็น** ต้องใช้เงื่อนไขอันดับสองเพื่อรับรองแม้แต่ local minimum (ส่วนที่ 7)
- Hessian ของลากรองเจียนขึ้นอยู่กับ state และอาจ indefinite; **Gauss-Newton** ($\nabla^2f \approx J_r^TJ_r$) หลีกเลี่ยงสิ่งนี้ เป็น PSD เสมอ และต้องการแค่อนุพันธ์อันดับหนึ่ง (ส่วนที่ 8)
- **SQP ชนะ interior-point สำหรับ MPC แบบ real-time** หลักๆ เพราะวิธี interior-point warm-start จากคำตอบที่อยู่บนขอบเขตได้ไม่ดี (ส่วนที่ 9)
- **Automatic differentiation** ใน reverse mode คำนวณ gradient เต็มด้วยค่าใช้จ่ายประมาณการประเมินฟังก์ชันหนึ่งครั้ง; CasADi ยังจัดการ sparsity และการสร้างโค้ด C ด้วย (ส่วนที่ 10)
- **RTI** — SQP iteration หนึ่งครั้งต่อ tick แบ่งเป็นเฟส preparation และ feedback — คือสิ่งที่ทำให้ NMPC ระดับ attitude-rate เป็นไปได้ ลด latency ที่แท้จริงเหลือระดับไมโครวินาที `acados` รวมสิ่งนี้ไว้ (ส่วนที่ 11)
- ลำดับการสร้าง: ตรวจสอบพลศาสตร์ offline → RK4 → IPOPT offline → วัดผล → ย้ายไป acados → เปลี่ยน PX4 interface เป็นอันสุดท้าย (ส่วนที่ 12)
